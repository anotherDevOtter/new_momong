# 얼굴 자동 측정 기준 — 확인·수정용 정리

> 이목구비 집중 분석(20항목)의 **자동 측정값이 어디서 어떻게 정해지는지**를 한 곳에 모은 문서.
> 정확도가 떨어지는 항목을 찾아 **어느 파일의 어느 값을 고치면 되는지** 바로 알 수 있게 했다.

## 0. 먼저 알아둘 것

측정은 3단계로 나뉜다.

```
사진 → [파이썬 face_landmark] 모듈별 측정 → grade(W/N/C 또는 S/N/H) + value
     → [백엔드] 그대로 전달 (python-analysis.service.ts)
     → [프론트 faceAnalysisToPosMap.ts] grade → 위치값(0.17 / 0.5 / 0.83)
     → [화면] 항목별 슬라이더 위치 · 다수결로 최종 이미지타입
```

| 단계 | 어디 | 고치는 것 |
|------|------|-----------|
| ① **등급 판정 기준(임계값)** | **파이썬 `face_landmark/analyze_face.py`의 모듈들** | 비율·각도 컷오프. **이 저장소에 없다** (아래 §5) |
| ② 항목 ↔ 모듈 연결 | `frontend/user/src/components/new/faceAnalysisToPosMap.ts` `FORM_TO_WNC` / `PROP_TO_SNH` | 어떤 모듈 결과를 어떤 화면 항목에 쓸지 |
| ③ 등급 → 위치값 | 같은 파일 `POS_LOW / POS_MID / POS_HIGH` | W/N/C 를 슬라이더 어디에 놓을지 |
| ④ 화면 라벨·순서·노출 | DB `module_configs` (admin 에서 편집) / `backend/src/module-configs/module-configs.service.ts` 시드 | 표 라벨 |
| ⑤ 최종 이미지타입 | `faceAnalysisData.ts` `dominantIdx` (항목별 다수결) | 타입 판정 |

> 사진 위 **가이드라인(메시·점선)은 표시용**이라 측정값에 영향이 없다.

## 1. 항목별 자동 측정 연결 (화면 20항목)

위치값: 왼쪽(l) = 0.17, 중간 = 0.5, 오른쪽(r) = 0.83. 등급 W/S → l, N → 중간, C/H → r.
(`⚠` = 연결이 근사이거나 의미가 어긋날 수 있는 것, `✗` = 자동 측정 없음 → "미측정", 디자이너가 직접 조정)

## 2. 디자이너 스펙표의 판정 기준 (`docs/face-analysis-data-mapping.md` 에서 가져옴)

파이썬이 이 기준대로 구현돼 있는지가 정확도 확인의 출발점이다. **스펙표가 있는 항목만** 적었다.

| 항목(모듈) | 측정 | W/S 쪽 | N | C/H 쪽 |
|------------|------|--------|---|--------|
| 광대 발달 (WNC 3) | 얼굴 측면 돌출 거리 | ≤ 0.5cm (미발달) | 0.5–1.0cm | ≥ 1.0cm (발달) |
| 눈썹 형태 (WNC 5) | 눈썹 헤드–꼬리 각 | ≤ 5° (둥글/내려감) | 6°–9° | ≥ 10° (각지고 올라감) |
| 눈 형태 (WNC 6) | 눈 세로:가로 | ≥ 1:3.5 (둥근 눈) | ≈ 1:4.0 | ≤ 1:4.5~5.0 (가로로 긴) |
| 입술 두께 (WNC 9) | 입술 세로:가로 | 세로 비중 큼 ≥ 1:3.5 | 1:4.0 내외 | 얇고 길음 ≤ 1:5.0 |
| 얼굴 길이 (SNH 2) | 얼굴 세로/가로 | 짧음 ≤ 1.3 | 평균 1.4~1.5 | 김 ≥ 1.51 |
| 눈썹과 눈 거리 (SNH 4) | 눈썹 하단~눈 중심 | 멀다 (기준 ❓) | 중간 1/5 | 가까움 ≤ 1/6 |
| 눈과 눈 사이 (SNH 5) | 두 눈 안쪽 간 / 얼굴 가로폭 | 넓다 ≥ 1/4.5 | 평균 1/5 | 좁다 ≤ 1/5.5 |
| 중안부 (SNH 11) | 중안부 비율 | 짧음 > 1.5:1 근접 | 평균 2:1 근접 | 길다 < 2.5:1 근접 |
| 코 폭 (SNH 10) | 콧망울 너비 / 얼굴 가로폭 | 좁음 ≤ 1/5.5 | 평균 1/5 | 넓음 ≥ 1/4.5 |
| 입 폭 (SNH 13) | 입폭 ≈ 양쪽 홍채 내측 간격 | 작음 < 홍채 간격 | 평균 = 홍채 간격 | 큼 > 홍채 간격 |

**스펙표에 없는 항목** — 파이썬 코드에서 직접 확인해야 한다:
페이스라인(턱 각도, 각도 기준 ❓) · 눈꼬리 각도 · 코 형태 · 쌍꺼풀 · 눈 바깥 여백 · 코 길이 · 인중 길이 · 턱 길이

## 3. 정확도가 떨어질 만한 곳 (점검 후보)

1. **3단계로만 쓴다.** 등급(W/N/C)을 0.17 / 0.5 / 0.83 으로 고정해 옮기므로, 경계값 근처의 얼굴은 연속 정보가 사라진다. 값을 주는 모듈(`value`)은 그 값으로 위치를 계산하는 방식도 가능하다 — 현재는 등급만 쓴다 (`gradeToPos`).
2. **근사로 연결한 항목 2개**: 코 너비(코 형태 모듈) · 상중하안부 비율(중안부 모듈). 의미가 정확히 같지 않아 결과가 어긋날 수 있다.
3. **방향(왼쪽/오른쪽)이 일치하는지**: 화면 항목의 왼쪽(l)/오른쪽(r) 의미와 모듈의 W·S / C·H 방향이 같아야 한다. 스펙표가 있는 항목은 일치한다. 없는 항목(눈꼬리·눈 바깥 여백·코 길이·인중·턱 길이)은 파이썬 정의를 확인해야 한다.
4. **자동 측정이 없는 3항목**은 판정(다수결)에 빠지므로 형태 축은 7개 항목만으로 정해진다.
5. **입력 사진 조건**: 랜드마크 기반이라 얼굴 기울기·표정·머리카락이 이마·윤곽·귀 쪽 값에 영향을 준다.
6. **모듈 번호는 불변 계약**이다 (과거 데이터와 연결). 번호를 바꾸지 말고 매핑 표(§1 ②)만 고친다.

## 4. 실제 값을 눈으로 확인하는 방법

- 관리자 화면 `/face-analysis-test` (`frontend/admin/src/app/face-analysis-test/page.tsx`)에서 사진을 올리면 **모듈별 grade / value / description 원본**이 나온다. 정확도 문제를 이 화면에서 항목별로 대조하는 게 가장 빠르다.
- 이목구비 집중 분석 화면에서 항목을 고르면 오른쪽에 "자동 측정됨" / "디자이너 확정" 배지와 측정 문구가 보인다 (`faceAnalysisToValues`).

## 5. 파이썬 측정 코드가 이 저장소에 없다

- 기준(임계값)을 실제로 정하는 코드는 `face_landmark/analyze_face.py` 의 모듈들이다 (문서에는 `../../face_landmark/` 로 적혀 있다).
- 백엔드는 `PYTHON_SERVER_URL` (로컬 `http://localhost:3201`) 로 사진 URL을 보내 결과를 받기만 한다 — [python-analysis.service.ts](../backend/src/face-analysis/python-analysis.service.ts).
- 임계값을 수정하려면 그 파이썬 저장소 위치가 필요하다. (현재 이 PC에서는 찾지 못했다.)

## 6. 이 문서로 바로 고칠 수 있는 것

| 하고 싶은 것 | 고칠 곳 |
|--------------|---------|
| 근사 연결 바로잡기 (예: 코 너비를 코 폭 모듈로) | `faceAnalysisToPosMap.ts` 의 `FORM_TO_WNC` / `PROP_TO_SNH` (단, 축이 다른 모듈이라 설계 확인 필요) |
| 등급을 위치로 옮기는 폭 조정 | 같은 파일 `POS_LOW / POS_MID / POS_HIGH` |
| 등급 대신 `value` 로 연속 위치 계산 | `gradeToPos` 를 모듈별 value 구간 변환으로 확장 |
| 자동 측정 없는 3항목 추가 | 파이썬에 모듈 추가 → 모듈 번호 부여 → 매핑 표에 한 줄 |
| 화면 라벨·순서 | admin 의 module_configs |
| 임계값(컷오프) | 파이썬 `face_landmark` |
