# 얼굴 분석 — 서버 데이터 ↔ 화면 표시 매칭표

> Step 6 [FaceAnalysisResult.tsx](../frontend/user/src/components/3way/FaceAnalysisResult.tsx) 가 표시하는 항목이
> 실제 서버(Python face_landmark) 어떤 모듈에 묶여 있는지 대조. **라벨 수정(F10)·비율 연결(F1) 작업의 기준 문서.**
>
> 출처:
> - 서버 모듈 키: [face_landmark/main.py](../../face_landmark/main.py) `wnc_modules` / `snh_modules` (응답 `results` 가 이 번호로 키잉)
> - 화면 바인딩: FaceAnalysisResult.tsx `WNC_KEY_BY_LABEL` / `SNH_KEY_BY_LABEL`
> - ⚠️ 응답 키 체계는 main.py(CLI) 기준. 운영 application.py 와 동일 가정 — 실제 응답 1건 덤프로 최종 확인 권장.

---

## 응답 구조 요약
```
AnalyzeResponse {
  wnc: { final: 'W'|'N'|'C', results: { '<모듈번호>': AnalysisModule } }
  snh: { final: 'S'|'N'|'H', results: { '<모듈번호>': AnalysisModule } }
}
AnalysisModule { name, grade('W'/'N'/'C' or 'S'/'N'/'H'), value?:number, description?, measurement?, image? }
```
- 화면은 모듈의 **grade** 로 체크 위치를 칠하고, 다수결로 최종 W/N/C·S/N/H 도출.
- 일부 모듈은 **`value`(수치)+`description`** 도 반환 (예: 중안부 `value:1.85, description:"중안부 비율 1.85 (S)"`). → 비율 연결(F1) 의 소스.

## ✅ 확정 목표 매핑 (디자이너 제공 스펙표 기준)

> 디자이너가 제공한 항목 정의 스펙표(측정 기준 + W/N/C·S/N/H 3단계)를 정답지로 채택.
> 각 행을 아래 모듈에 바인딩하고, 칸 텍스트(현재 "중간" placeholder)를 스펙 문구로 교체.
> ❓ = 이미지에서 잘려 미확인 — 구현 전 확인 필요.

### WNC 목표 (7행) — `WNC_KEY_BY_LABEL` 교체
| 항목 | 모듈키 | 측정 기준 | Warm | N | Cool |
|------|:--:|------|------|------|------|
| 피부톤 | 1 | ❓세로:가로 비율 (피부톤과 안 맞음 — 확인) | 세로비중 큼 ≥1:3.5 | 1:4.0 내외 | 얇고 길음 ≤1:5.0 |
| 페이스라인 | 2 | 좌·우 귀밑–턱끝 간 ❓각도 | 둥근 | 균형 | 각진 |
| 광대 발달 정도 | **3** ← (현재 4) | 얼굴 측면 돌출 거리 | ≤0.5cm(미발달) | 0.5–1.0cm | ≥1.0cm(발달) |
| 눈썹 형태 | 5 | 눈썹 헤드–꼬리 각 | ≤5°(둥글/내려감) | 6°–9° 균형 | ≥10°(각지고 올라감) |
| 눈 형태 | 6 | 세로:가로 비율 | ≥1:3.5(둥근눈) | ≈1:4.0 | ≤1:4.5~5.0(가로로 긴) |
| 코 형태 | 8 | 코 형태 | 둥글다 | 평균형 | 뾰족하다 |
| 입술 두께 | 9 | 세로:가로 비율 | 세로비중 큼 ≥1:3.5 | 1:4.0 내외 | 얇고 길음 ≤1:5.0 |

**변경점**: 윤곽라인(4) → **광대 발달 정도(3)** 로 행 교체. 나머지는 라벨 정밀화 + 칸 문구 추가(키 유지).

### SNH 목표 (6행, 피부톤 제외) — `SNH_KEY_BY_LABEL` 전면 교체
| 항목 | 모듈키 | 측정 기준 | Soft | N | Hard |
|------|:--:|------|------|------|------|
| 얼굴 길이 | 2 | 얼굴 세로/가로 비율 | 짧음 ≤1.3 | 평균 1.4~1.5 | 김 ≥1.51 |
| 눈썹과 눈 거리 | 4 | 눈썹 하단~눈 중심 거리 | 멀다(≥얼굴길이의 ❓) | 중간 1/5 | 가까움 ≤1/6 |
| 눈과 눈사이 거리 | 5 | 두 눈 안쪽 간 거리/얼굴 가로폭 | 넓다 ≥1/4.5 | 평균 1/5 | 좁다 ≤1/5.5 |
| 중안부 | 11 | 비율 | 짧음 >1.5:1 근접 | 평균 2:1 근접 | 길다 <2.5:1 근접 |
| 코 폭 | 10 | 콧망울 너비/얼굴 가로폭 | 좁음 ≤1/5.5 | 평균 1/5 | 넓음 ≥1/4.5 |
| 입 폭 | 13 | 입폭 ≈ 양쪽 홍채 내측 간격 | 작음<홍채간격 | 평균=홍채간격 | 큼>홍채간격 |

**변경점**: 7행(피부톤·얼굴밸런스·가로비율·세로비율·눈썹밀도·코폭·입술폭) 전부 폐기 → 위 6행으로 재구성.
모듈 2/4/5/11/10/13 에 정확히 바인딩 (전부 서버가 보내는 활성 모듈).

### 칸 텍스트 채우기 (현재 placeholder 문제)
현재 base 배열은 `warm/cool/soft/hard` 컬럼을 `''` 빈값, `neutral: '중간'` 으로만 둠 → 화면에 "중간"만 표시.
스펙표의 각 단계 문구를 base 배열의 warm/neutral/cool (soft/neutral/hard) 에 채워야 표가 의미를 가짐.

### 비율 3종 (F1) — 별도지만 같은 모듈 재활용
- 중안부: SNH_11 `value` → 표기 변환
- 가로세로: SNH_02 face_length `value`(=세로/가로) → 표기 변환
- 상중하(세로 1:1:1): ❓ 단일 모듈 없음 — 별도 계산 또는 보류 결정 필요

## 구현 전 확인 사항
1. WNC 피부톤·페이스라인 측정기준 칸 (이미지 잘림)
2. SNH "눈썹과 눈 거리" Soft 임계값 (잘림)
3. 비율 상중하(세로) 소스
4. **실제 응답 1건 덤프**로 모듈 2/4/5/11/10/13/광대3 의 grade·value 실재 확인 (특히 광대3, 입폭13, 코폭10 이 운영 응답에 실제로 오는지)
